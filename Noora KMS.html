Overview

The /api/discovery/getData API allows you to query content and profile data from your platform. It provides powerful filtering, sorting, searching, and pagination capabilities.

POSThttps://okf-be-prod-dot-ok-framework.el.r.appspot.com/api/discovery/getData

Authentication

All API requests must include your API token in the x-auth-token header and your tenant identifier in the tenant header.

Parameter
Type
Required
Description
x-auth-tokenstring

Your API authentication token

tenantstring

Your tenant identifier string 

curl -X POST https://okf-be-prod-dot-ok-framework.el.r.appspot.com/api/discovery/getData \
  -H "x-auth-token: YOUR_TOKEN_HERE" \
  -H "tenant: YOUR_TENANT_IDENTIFIER_STRING"

Request Format

The request body must contain a configs property whose value is a JSON-stringified object. This is important — the configs value must be passed through JSON.stringify() before sending. 

curl -X POST https://okf-be-prod-dot-ok-framework.el.r.appspot.com/api/discovery/getData \
  -H "x-auth-token: YOUR_TOKEN_HERE" \
  -H "tenant: YOUR_TENANT_IDENTIFIER_STRING" \
  -d '{
    "configs": "{\"contentTypes\":[\"articles\"],\"limit\":10,\"skip\":0,\"countData\":true}"
  }'

Core Parameters

These are the primary parameters available inside the configs object. You must provide either contentTypes or profileTypes (but not both).

Parameter
Type
Required
Description
contentTypesstring[]Conditional

Array of content type identifiers to query. Required if profileTypes is not provided. Mutually exclusive with profileTypes. Example: ["stories", "articles", "reports"]

profileTypesstring[]Conditional

Array of profile type identifiers to query. Required if contentTypes is not provided. Mutually exclusive with contentTypes. Example: ["volunteers", "coreTeam", "researchers"]

limitnumberNo

Number of documents to return per request. Used for pagination. Default: returns all matching documents (no limit).

skipnumberNo

Number of documents to skip. Used with limit for pagination. Default: 0. Start at 0, then use the skip value returned in the response for the next page.

activeSortobjectNo

Object with field paths as keys and sort direction as values. Use 1 for ascending and -1 for descending. Example: {"createdAt": -1, "meta.title": 1}. Default: {} (no sorting).

searchTermstringNo

Full-text search query. When provided, results are returned in relevance order. Example: "climate change". Default: none (no search filtering).

projectionobjectNo

MongoDB-style projection to select which fields to include (1) or exclude (0) in the response. Example: {"meta.title": 1, "meta.description": 1, "createdAt": 1}. Default: {} (all fields returned).

countDatabooleanNo

When set to true, the response includes a count field with the total number of matching documents. Useful for building pagination UIs. Default: true.

findQueryobjectNo

Additional MongoDB query conditions to merge with the generated query. Example: {"status": "published", "createdAt": {"$gte": "2024-01-01"}}. Default: {} (no additional conditions).

Filtering

The activeFilters parameter allows you to apply structured filters to your query. Each filter is an object with a target (defining what to filter on) and values (the filter criteria).

Filter Structure

Each filter in the activeFilters array follows this structure: 

{
  "activeFilters": [
    {
      "target": {
        "filterType": "tagType",     // The type of filter
        "tagType": "category",       // Filter-specific config
        "valuePath": "path.to.field" // Used by some filter types
      },
      "values": ["value1", "value2"] // The values to filter by
    }
  ]
}

Rollup Relationship Filter (rollupRelationshipType)

Filters content based on tags applied to a related user profile. This is useful when your content has a reference to a user (e.g., the author), and you want to filter that content based on something the user's profile is tagged with. For example, say you have "stories" and each story has an author reference at meta.kp_contributed_by. Each author has a "volunteers" profile that is tagged with "states". If you want to find all stories written by authors from Karnataka, this filter lets you do exactly that — it looks up all user profiles tagged with the selected state, collects their user IDs, and then filters stories where meta.kp_contributed_by matches those user IDs. How it works internally: 1. Searches across all user profile types (e.g., volunteers, coreTeam) for profiles tagged with the selected values under the specified tag type. 2. Extracts the user id from each matching profile. 3. Filters the content where the relationshipValuePath field matches any of those user IDs.

Parameter
Type
Required
Description
target.filterTypestringYes

"rollupRelationshipType"

target.tagTypestringYes

The tag type applied to user profiles that you want to filter by. Example: "states" — to filter content by the state the author's profile is tagged with.

target.relationshipValuePathstringYes

The dot-notation path in the content document that holds a reference to the user. Example: "meta.kp_contributed_by" — the field that stores the author's user ID.

valuesstring[]Yes

Array of tag IDs to match against the user profiles. These are IDs from the tag type specified in target.tagType. Example: an array of state IDs. 

// Find all stories written by authors from Karnataka
{
  "activeFilters": [
    {
      "target": {
        "filterType": "rollupRelationshipType",
        "tagType": "states",
        "relationshipValuePath": "meta.kp_contributed_by"
      },
      "values": ["673d8531d6ef55f9b7958e6d"]
    }
  ]
}

Nested Rollup Tag Filter (nestedRollupTagType)

Filters content by traversing a hierarchy of tag relationships. Use this when your content is tagged at a low level in a hierarchy, but you want to filter by a higher level. For example, suppose your platform has a location hierarchy: Countries → States → Cities, and your stories are tagged with cities. If a user selects "Karnataka" (a state), this filter will: 1. Find all cities tagged with Karnataka. 2. Return all stories tagged with any of those cities. This saves you from manually collecting all the city IDs under a state — the API resolves the hierarchy for you. The rollupPath array defines this hierarchy from bottom to top. The first element is the tag type your content is directly tagged with, and the last element is the level the user is selecting from. Hybrid mode: The last element in rollupPath can also be a field path (starting with main.) instead of a tag type. This is useful when the highest level in your hierarchy is a dropdown/radio field on a tag type rather than a separate tag type itself. For example, if states have a main.region.value field with values like "North" or "South", you can use ["cities", "states", "main.region.value"] to filter content by region — it will find all states where that field matches, then find all cities tagged with those states, and return matching content.

Parameter
Type
Required
Description
target.filterTypestringYes

"nestedRollupTagType"

target.rollupPathstring[]Yes

An array defining the tag hierarchy from bottom (closest to content) to top (what the user selects). The first element is the tag type the content is directly tagged with. The last element is either a tag type or a field path (starting with "main.") that the user selects from. Must have at least 2 elements. Example: ["cities", "states", "countries"]

valuesstring[]Yes

Array of IDs (if the last rollupPath element is a tag type) or field values (if it is a field path) to filter by. Example: a state ID to get all content tagged with any city within that state. 

// Find stories tagged with cities in Karnataka
{
  "activeFilters": [
    {
      "target": {
        "filterType": "nestedRollupTagType",
        "rollupPath": ["cities", "states"]
      },
      "values": ["673d8531d6ef55f9b7958e6d"]
    }
  ]
}

Rollup Value Path Filter (rollupValuePathType)

Filters content based on a field value in a related collection. Use this when your content references (or is tagged with) documents from another collection, and you want to filter based on a field inside those referenced documents. For example, suppose your "stories" have an author reference at meta.kp_contributed_by pointing to a document in the users collection. Each user has a role field (e.g., "admin", "superAdmin"). If you want to find all stories written by superAdmins, this filter will: 1. Look up the users collection and find all users where role equals "superAdmin". 2. Collect their IDs. 3. Return all stories where meta.kp_contributed_by matches any of those user IDs. This filter supports two variations based on how the content relates to the target collection: Collection reference: The content has a direct field (like an ObjectId) pointing to a document in another collection. Use collectionToRollup + valuePathToRollup. Tag-based reference: The content is tagged with documents from a tag type collection. Use tagTypeCollectionToRollup instead — the filter will match against the tag reference path automatically. You cannot use both collectionToRollup and tagTypeCollectionToRollup in the same filter.

Parameter
Type
Required
Description
target.filterTypestringYes

"rollupValuePathType"

target.collectionToRollupstringConditional

The name of the collection to look up. Required when filtering via a direct field reference (not tags). Use this OR tagTypeCollectionToRollup, not both. Example: "users"

target.valuePathToRollupstringConditional

The dot-notation path in the content document that holds the reference to the target collection. Required when using collectionToRollup. Example: "meta.kp_contributed_by"

target.tagTypeCollectionToRollupstringConditional

The tag type collection to look up. Use this when the content is tagged with documents from this collection (instead of having a direct field reference). The filter will automatically match against the tag path tags.<tagType>.data._id. Use this OR collectionToRollup, not both. Example: "cities"

target.valuePathInRolledUpCollectionstringYes

The dot-notation path to the field in the target collection that you want to filter by. Example: "role" (to filter users by their role field)

valuesstring[]Yes

Array of field values to match in the target collection. These are matched against the field specified in valuePathInRolledUpCollection. Example: ["superAdmin"] 

// Find stories written by superAdmins
{
  "activeFilters": [
    {
      "target": {
        "filterType": "rollupValuePathType",
        "collectionToRollup": "users",
        "valuePathToRollup": "meta.kp_contributed_by",
        "valuePathInRolledUpCollection": "role"
      },
      "values": ["superAdmin"]
    }
  ]
}

Advanced Features

These parameters provide advanced querying capabilities for complex data retrieval needs.

Aggregation

Enable MongoDB aggregation pipeline for complex data operations like grouping and lookups.

Parameter
Type
Required
Description
useAggregationobjectNo

Enable aggregation mode. Contains configuration for aggregation behavior. Default: false (disabled).

useAggregation.groupByWithLookupbooleanNo

When true, enables grouping results with lookup joins in the aggregation pipeline.

Faceting

Group results by field values to get counts per category. Useful for building filter UIs.

Parameter
Type
Required
Description
facetarrayNo

Array of faceting configurations. Each item defines a field to group by and count. 

{
  "contentTypes": ["articles"],
  "facet": [
    { "field": "category", "tagType": "category" }
  ],
  "countData": true
}

Population

Expand reference fields to include full documents instead of just IDs. Similar to SQL JOINs.

Parameter
Type
Required
Description
populationarrayNo

Array of MongoDB populate configuration objects. Each object specifies a path (the reference field) and optionally select (fields to include from the referenced document). Example: [{"path": "meta.kp_contributed_by", "select": "name email"}] 

{
  "contentTypes": ["articles"],
  "population": [
    { "path": "meta.kp_contributed_by", "select": "name email avatar" },
    { "path": "tags", "select": "main.title" }
  ],
  "limit": 10
}

Lookup Config

Alternative to population using MongoDB's $lookup aggregation stage. Provides more control over joined data.

Parameter
Type
Required
Description
lookupConfigarrayNo

Array of lookup configuration objects for aggregation-based population. Uses MongoDB $lookup syntax.

Pagination Pattern

Use the skip value from each response to fetch subsequent pages. When skip is undefined or absent, you've reached the last page.

Code Examples

Complete working examples for common use cases.

Basic Query

Fetch the 10 most recent articles with title and description. 

curl -X POST https://okf-be-prod-dot-ok-framework.el.r.appspot.com/api/discovery/getData \
  -H "x-auth-token: YOUR_TOKEN_HERE" \
  -H "tenant: YOUR_TENANT_IDENTIFIER_STRING" \
  -d '{
    "configs": "{\"contentTypes\":[\"articles\"],\"limit\":10,\"skip\":0,\"activeSort\":{\"createdAt\":-1},\"projection\":{\"meta.title\":1,\"meta.description\":1,\"createdAt\":1},\"countData\":true}"
  }'

Filtered Query with Search

Search for articles about 'climate' within a specific category and date range. 

curl -X POST https://okf-be-prod-dot-ok-framework.el.r.appspot.com/api/discovery/getData \
  -H "x-auth-token: YOUR_TOKEN_HERE" \
  -H "tenant: YOUR_TENANT_IDENTIFIER_STRING" \
  -d '{
    "configs": "{\"contentTypes\":[\"articles\"],\"searchTerm\":\"climate\",\"activeFilters\":[{\"target\":{\"filterType\":\"tagType\",\"tagType\":\"category\"},\"values\":[\"CATEGORY_TAG_ID\"]},{\"target\":{\"filterType\":\"dateRangeType\",\"path\":\"createdAt\"},\"values\":[{\"start\":\"2024-01-01T00:00:00.000Z\",\"end\":\"2024-12-31T23:59:59.999Z\"}]}],\"limit\":20,\"countData\":true}"
  }'

Query with Population

Fetch articles with their contributor profiles expanded. 

const configs = {
  contentTypes: ["articles"],
  limit: 10,
  population: [
    { path: "meta.kp_contributed_by", select: "name email avatar" },
    { path: "tags", select: "name slug" }
  ],
  activeSort: { createdAt: -1 },
  countData: true
};

const response = await fetch("https://okf-be-prod-dot-ok-framework.el.r.appspot.com/api/discovery/getData", {
  method: "POST",
  headers: {
    "x-auth-token": "YOUR_TOKEN_HERE",
    "tenant": "YOUR_TENANT_IDENTIFIER_STRING"
  },
  body: JSON.stringify({ configs: JSON.stringify(configs) })
});

const { data } = await response.json();
// data[0].meta.kp_contributed_by is now a full object: { name: "...", email: "...", avatar: "..." }
